# Website integration plan

## Current repository findings

The project declares Docusaurus 3.9.2 in `package.json`. Existing lessons are Markdown/MDX in `docs/`, and `sidebars.js` uses an autogenerated sidebar. Current files include explicit slugs. The planning package does not modify them or the site configuration.

## Integrating a ready page

1. Confirm its tracker status, source/rights review, required media, and prerequisite pages. Resolve essential unpublished dependencies as a batch.
2. Inspect `docusaurus.config.js`, `sidebars.js`, existing page metadata, and the working tree. Confirm the actual docs route prefix before choosing URLs.
3. Move the draft to its intended `docs/` path. Use a stable ID, title, description, slug, and sidebar position. Custom editorial status metadata does not by itself prevent publication; keep unready files outside `docs/`.
4. Resolve links against the destination paths. Link canonical lessons instead of duplicating explanations. Keep heading anchors stable where practical.
5. Add category metadata or explicit sidebar groups when needed. Use friendly labels; keep empty paths out of navigation.
6. Put cleared media in the appropriate static directory, with accessible descriptions and recorded attribution. Do not embed unapproved copied scores or charts.
7. Record old and new public routes. Prefer retaining existing slugs; when routes must change, implement redirects using the actual hosting/site mechanism and test the old URL. Moving a file is not a redirect.
8. Run `npm run build` in the website project. Review affected pages at desktop and narrow mobile widths: headings, tables, notation, media controls, previous/next links, and keyboard navigation. Record what was actually checked.
9. Remove the obsolete draft copy after its canonical content is integrated. Update the tracker to integrated. Mark published only after authorized deployment is confirmed.
